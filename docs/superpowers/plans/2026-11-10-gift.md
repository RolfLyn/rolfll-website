# Gift Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A reusable "gift" on the reader site: she unwraps a box, taps through reveal screens, picks a day; he marks it booked in admin and she sees the booking.

**Architecture:** A pure model module `worker/gift.ts` (checking, state changes, the reader view), a views module `worker/gift-views.ts` (page, script, admin), and routes in `worker/index.ts` mirroring the special event. Shared JSON-check helpers move out of `worker/event.ts` into `worker/json-checks.ts`.

**Tech Stack:** Cloudflare Worker (TypeScript), KV `NOTES`, R2 `MEDIA`, server-rendered HTML with inline ES5 script, vitest.

**Spec:** `docs/superpowers/specs/2026-11-10-gift-design.md`

## Global Constraints

- Public repo: no private content (places, dates of the real gift, text, photos). Tests use placeholders.
- No em dashes in any copy.
- Her iPhone is the target; inline ES5 script only; every action also works without JavaScript.
- "Today" for the gift is `noteDay(now)` from `worker/dates.ts` (turns at 4am Singapore).
- KV keys: `gift`, `gift_state`, `gift_photos`. Photos served `no-store`, behind her session, from our storage only.
- Copy fixed by the spec: "Untie the ribbon", "Change the day", "It's booked", "BOOKED", "See it again", "That didn't save. Try again?", "Photo credits".
- Saves need session + CSRF; XHR with form fallback; `quiet=1` returns the quiet response as the event does.
- `prefers-reduced-motion`: no lid lift, no screen transitions.

## Review Focus

1. Corrupt `gift` or `gift_state` in KV: the notes page still renders (no gift card), `/gift` shows an error page, admin still opens with the problem named.
2. The day boundary: at 03:59 Singapore on the day before a listed day she can pick it; at 04:00 on that day she cannot.
3. Her pick arriving after he marked it booked (two tabs): refused, booking untouched.
4. He marks booked from a stale page after she changed day: refused with a message, nothing written.
5. A gift photo requested without her session, before `from` or after `until`: 404.

### Task 1: Shared checks and the gift model

**Files:**
- Create: `worker/json-checks.ts`, `worker/gift.ts`
- Modify: `worker/event.ts` (import the helpers instead of defining them)
- Test: `tests/notes-gift.test.ts`

**Interfaces:**
- Produces in `json-checks.ts`: `class Problem extends Error`, `isObject(v)`, `text(v, max, where, optional?)`, `id(v, where, max)`, `date(v, where)`, `list(v, max, where)`; messages unchanged so existing event tests still pass.
- Produces in `gift.ts`:
  - `GIFT_LIMITS = { id: 40, title: 120, kicker: 40, heading: 120, text: 600, tag: 30, next: 40, line: 200, days: 8, reveals: 6, photos: 2, summary: 4, credits: 6, credit: 300, bookingLines: 4, bookingLine: 160 }`
  - Types `Gift`, `GiftReveal { kicker, heading, text, photos: string[], next }`, `GiftDay { id, name, heading }`, `GiftState { giftId, unwrapped?, pick?: { day, at }, history: { day, at }[], booked?: { day, lines: string[], at }, bookedSeen? }`, `GiftStage = 'box' | 'pick' | 'chosen' | 'booked'`, `ReaderGift { title, box, reveals: (Omit<GiftReveal,'photos'> & { photoKeys: string[] })[], pick, days: (GiftDay & { num: string, weekday: string, month: string, open: boolean })[], chosenLine, summary, pendingLine, bookedLine, credits: string[], stage: GiftStage, chosen?: GiftDay, booking?: string[] }`
  - `checkGift(source: string, photos: EventPhoto[], state: GiftState | null): { ok: true; gift: Gift } | { ok: false; error: string }`
  - `parseStoredGift(raw: string | null): Gift | null` (throws on corrupt), `parseGiftState(raw: string | null, giftId: string): GiftState` (throws on corrupt; other giftId gives `emptyGiftState(giftId)`), `emptyGiftState(giftId): GiftState`
  - `unwrapGift(s, at)`, `pickGiftDay(s, gift, day, today, at): GiftState | null`, `parseBookingLines(text): { lines: string[] } | { error: string }`, `markBooked(s, day, lines, at): GiftState | null`, `undoBooked(s)`, `seeBooked(s, at)`
  - `isGiftShowing(gift, today)`, `giftStage(gift, s)`, `readerGift(gift, s, photos, today): ReaderGift`, `giftWaiting(gift, s): boolean`, `giftPhotoKeys(gift, photos): string[]`, `giftPhotoNames(gift): string[]`
- Reuses `EventPhoto` and `parsePhotos` from `worker/event.ts`.

- [ ] **Step 1: Write the failing tests** in `tests/notes-gift.test.ts` with a placeholder gift (`id: 'g1'`, days `2027-01-04`..`2027-01-07`, `from: '2026-11-01'`, `until: '2027-01-07'`, one reveal with photo `a.jpg`):
  - `checkGift` accepts it; refuses, naming the problem: bad JSON, `until` before the last day ("until" must be on or after the last day), a duplicate day id, 0 or 9 days, 7 reveals, 3 photos on a reveal, a photo not uploaded, a day id that is not a real date.
  - with a state holding a pick of `2027-01-06`: a save changing `id` or dropping `2027-01-06` is refused with a message containing "clear her pick first"; with an empty state both are accepted.
  - `parseGiftState('{"giftId":"other",...}', 'g1')` is empty; corrupt JSON throws.
  - `pickGiftDay` at today `2027-01-04`: `2027-01-04` refused (null), `2027-01-05` accepted; a missing day refused; refused when `booked` is set; a second pick replaces `pick` and appends both to `history`.
  - `unwrapGift` keeps the first time on a second call.
  - `markBooked(s, '2027-01-05', …)` is null when the pick is `2027-01-06` or there is no pick; `parseBookingLines` drops blank lines, refuses 0 or 5 lines and a line over 160.
  - `giftStage`: `box` → `pick` after unwrap → `chosen` after a pick → `booked` after `markBooked` → `chosen` after `undoBooked`; a pick whose day was removed from the gift gives `pick`.
  - `giftWaiting`: true before unwrap; false after unwrap; true after booking; false after `seeBooked`; a second `markBooked` for the same day (editing the lines) keeps `booked.at`, so it stays false.
  - `readerGift` maps photo names to keys, marks `open` false for days on or before today, and contains no `history`.
  - `isGiftShowing` is inclusive of `from` and `until`.

### Task 2: Her page and the admin page

**Files:**
- Create: `worker/gift-views.ts`
- Test: `tests/notes-gift-views.test.ts`

**Interfaces:**
- Consumes: `ReaderGift`, `Gift`, `GiftState`, `EventPhoto` from Task 1; `shell`, `READER_FONTS`, `adminShell`, `escapeHtml`, `errorLine`, `formatStamp` from `worker/views.ts`.
- Produces: `GIFT_SCRIPT: string`; `giftPage({ view, home, mediaBase, saveAction?, csrf?, back, preview? }): string`; `giftErrorPage(): string`; `giftAdminPage({ base, csrf, text, error?, flash?, photos, gift: Gift | null, state: GiftState | null, today }): string`.

- [ ] **Step 1: Write the failing tests:**
  - every screen is in the HTML in order (`data-screen="box"`, one `data-screen="reveal"` per reveal, `"pick"`, `"chosen"` or `"booked"`), and `data-start` on the root names the stage's screen (`box`, `pick`, `chosen`, `booked`).
  - the box button is a form posting `do=unwrap` to `saveAction` with the CSRF; each open day is a form button posting `do=pick&day=<id>`; a closed day renders `disabled` and no form.
  - chosen screen shows the chosen day's heading, `chosenLine`, the summary lines, `pendingLine` and "Change the day"; booked screen shows "It's booked", each booking line escaped, "BOOKED", `bookedLine`, and no "Change the day".
  - "See it again" appears on chosen and booked screens only.
  - user text is escaped (`<b>` in a heading becomes `&lt;b&gt;`); photos use `mediaBase/<key>`; credits sit behind "Photo credits".
  - preview (`preview: true`, no `saveAction`) has no forms that save and no `data-csrf`.
  - the style has a `prefers-reduced-motion` block; the page contains `GIFT_SCRIPT`; no em dash anywhere in `GIFT_SCRIPT` or the page.
  - admin: textarea with the JSON, photo upload (`name="photos"` multiple), status lines ("Not opened yet", "Unwrapped", "Picked <heading>"), history; the "Mark as booked" form (hidden `day` equal to her pick, textarea `lines`) only when she has a pick and it is not booked; when booked, the lines, an edit form and "Undo booked" with `confirm(`; "Clear her pick" with `confirm(`; a Preview link to `/admin/gift/preview`.
- [ ] **Step 2: Run** `npx vitest run tests/notes-gift-views.test.ts` — Expected: FAIL, module not found.
- [ ] **Step 3: Implement `worker/gift-views.ts`** matching the approved mockup (`gift-flow.html` in the builder's scratchpad `mock3`) as described in the spec: night sky with stars, gold uppercase kickers, Cormorant Garamond headings, Caveat for `tag`, `chosenLine`, `bookedLine`; red box with gold ribbon and bow, lid lifting on unwrap; tilted white-bordered photos; 2-column day tiles, chosen filled gold; cream paper card; rose rotated stamp. `GIFT_SCRIPT`: shows one screen at a time starting at `data-start`; buttons move to the next screen; the box button posts `do=unwrap&quiet=1` by XHR then moves on (on failure it still moves on: unwrapping is not lost, the server records it on the next pick); tile taps select and rename the confirm button to "<name> it is"; confirm posts `do=pick&quiet=1` and on success shows the chosen screen with that day filled in, on failure stays and shows "That didn't save.
